# OpenSpec ドキュメントを下書きする（作業計画ワークフロー）

利用者と相談しながらドキュメントページを作成します。ページ内で計画とレビューを行い、節を 1 つずつ執筆します。執筆を始める前に、文体の基準となる`write-openspec-docs`と`no-ai-slop`を読み込んでください。

## 1. 作業用の節を準備する

ページをタイトルと`>`で始まる目標行だけにして、その下に作業用の節を追加します。

```md
## 作業用：ページ計画（公開前に削除）

### 目的

### 構成
```

- **目的**：3〜5 個の箇条書き。読者と調べたい内容、ページで扱う内容、ほかのページへ案内する内容を記載します。執筆前に`docs-lab/README.md`の目標行と、`docs-lab/message-map.md`からこのページへ割り当てられた質問を確認してください。
- **構成**：ページの各節を番号付きリストにします。1 行ごとに節名と内容の形式（表、コードフェンス、ツリー、箇条書き）を記載します。
- ページで扱わない内容ではなく、扱う内容を書きます。平易な言葉と短い箇条書きを使ってください。利用者はエディターでこの計画を読みます。

## 2. 計画が承認されるまで調整する

- 計画の修正は容易ですが、ページ本文の修正には手間がかかります。執筆前に、利用者が求める回数だけ計画を調整してください。
- すべての決定をチャットだけでなく計画自体にも記録します。ほかのページで対応する項目や、作業中に見つけた製品上の所見を記録する`### メモ`リストを追加してください。
- 利用者がターンの間にファイルを直接編集する場合があります。その編集は決定事項であり、元に戻すべき差異ではありません。
- 未決定事項は推奨案を添え、1 つずつ提示します。

## 3. 執筆計画を追加し、手順ごとに執筆する

構成が固まったら、メモの下に`### 執筆計画`を追加します。ページの各節に 1 つの手順を割り当て、ID と分かりやすいタイトル（`**D1. 目標行と導入**`）を付けてください。最後に統合手順（ほかのページの更新）とクリーンアップ手順を置きます。その後、次のように進めます。

- 利用者が手順 ID を指定するまで待ちます。指定された手順だけを執筆し、作業用ブロックより上のページ本文へ追加します。
- 記述前に、各事実をソースと照合します。推測せず、簡単な grep でも確認してください。リファレンスでは、生の契約（テンプレート、指示、設定）を言い換えずコードフェンスへそのまま掲載し、GitHub 上のファイルへリンクします。
- 同列の節では繰り返し使える小構造を揃え、ページ全体を 1 つの仕組みとして読み取れるようにします。
- 計画内の手順へ`（完了）`と記載し、反映内容と次の手順を報告します。

## 4. 統合とクリーンアップ

- **統合**：ページを参照するすべての箇所を更新します。ページの`>`行と完全に一致する README の目標行、メッセージマップ、同期設定（`website/docs.sync.config.mjs`）、ツリー全体を grep して見つけた相互リンクが対象です。`node website/scripts/sync-docs.mjs`を実行して検証します。
- **クリーンアップ**：作業用ブロックを削除し、`write-openspec-docs`の検索可能性テストと一覧性テストをデスクトップ幅と狭い幅で実施します。本文が完成したら、メッセージマップの該当行を「回答済み」へ変更します。
