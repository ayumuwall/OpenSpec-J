# OpenSpec ドキュメントを検証する

完成したドキュメントの記述を事実と照合します。新規コンテキストを使うのは、レビュー担当が執筆過程を見ておらず、執筆者の前提に引きずられないようにするためです。

このスキルは、利用者が依頼した場合だけ実行します。執筆は`write-openspec-docs`が担当します。利用者が検証を依頼しない限り、執筆セッション内からこのスキルを起動しないでください。

## 検証範囲を決める

1. 対象を確認します。ページ、1 つの`##`節、変更した記述の一覧のいずれかです。対象が指定されていなければ確認してください。
2. 対象が属するドキュメントツリーのルートにある README を読みます。そこに記載された不変条件とページマップも検証対象です。
3. 単位ごとに 1 つのサブエージェントを使います。単位は 1 つの`##`節、または指定された記述の一覧です。ページ全体を検証する場合は複数のサブエージェントを並列実行します。

## レビュー担当を起動する

汎用サブエージェントを使います。サブエージェントはスキルを継承しないため、プロンプト内で必要な情報をすべてパスで渡します。すべてのプレースホルダーを埋め、各パスを絶対パスにして送信してください。

```
OpenSpec の利用者向けドキュメントを担当者へ渡す前に、1 単位をレビューします。初見で疑いながら読む開発者と、リポジトリを開いて確認するファクトチェッカーという、最も厳しい 2 人の読者の視点を持ってください。

リポジトリルート：<リポジトリの絶対パス>。すべてのツールで絶対パスを使用してください。

最初に読むもの：
1. <ドキュメントツリーのルート>/README.md：ページマップと常設の不変条件。
2. <リポジトリの絶対パス>/.agents/skills/write-openspec-docs/writing.md：文体規則。
3. <ページのパス>：<「<見出し>」節 | 次の変更した記述：<一覧>>だけをレビューします。文脈を把握するため、ページのほかの部分も読んでください。

次の順序で確認します。

1. 事実。すべてのコマンド、フラグ、パス、設定キー、出力ブロック、既定値、動作に関する記述を確認します。掲載されたターミナルコマンドを再実行してください。読み取り専用コマンドは任意の場所で、状態を変更するコマンドは作業用ディレクトリだけで実行します。実行できない場合は実行しません。AI チャット用のコマンド（/opsx:propose など）はシェルで実行できません。名前と動作を、このリポジトリに含まれるスキルのソースと照合します。名前は src/ と CLI 自身の --help でも確認してください。出力ブロックは、コマンドが実際に表示する内容と一致する必要があります。
2. 例。仕様や変更提案の例は、すべて`openspec validate`を通過する必要があります。例がディスク上に存在する場合は実行してください。
3. 構成。正式な説明先が別ページにある話題を重複して説明している箇所や、ドキュメントツリーの README にある規則へ違反する箇所を指摘します。
4. 役割との一致。その単位がページに明記された役割を果たしているか確認します。タイトル直下に 1 行の説明があれば、それが役割です。読者が求める情報へすぐ到達できるかも確認します。
5. 信頼性と冗長表現。誇張や安心感を与える形容詞（簡単、シンプル、強力、シームレス）、根拠を示さない主張、具体的な事実を示すべき箇所での曖昧な一般化、二項対立（「X ではなく Y」）、コロンで結論を後出しする文、重要性の誇張、要約だけの結び、em ダッシュ、文章にすべき箇条書き、短く強い並列表現を 3 文続ける構成を指摘します。

指摘事項だけを重大度順に報告してください。各項目では、該当行を引用し、問題点を説明して、修正案を 1 行で示します。検証したすべての事実について、実行したコマンド、または確認したファイルと行を示します。検証できなかった記述と理由も列挙してください。その単位を書き直してはいけません。問題がない場合はその旨を伝え、検証した内容を正確に列挙します。
```

## レポートを処理する

- 既定では書き直さず、レポートだけを提示します。重大度順の指摘、該当行の引用と 1 行の修正案、検証した内容と方法、レビュー担当が検証できなかった記述を利用者へ示してください。
- 利用者が検証と修正の両方を依頼した場合、または指摘事項を承認した場合だけ修正します。検証側が誤っている場合もあります。指摘を採用しない場合は理由とともにレポートへ記載し、利用者が最終判断できるようにします。
- 修正によって事実に関する記述が変わった場合は、変更した記述だけを再検証します。誤字や表現だけの修正には 2 回目の検証は不要です。
- 2 回実施しても収束しない場合は停止し、利用者へ判断を求めます。繰り返し修正し続けないでください。
