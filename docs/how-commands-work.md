# コマンドの仕組み

**知っておくべき 1 つのこと: OpenSpec には 2 種類のコマンドがあり、それらは 2 つの異なる場所で実行されます。**

- `openspec ...` コマンドは **ターミナル** で実行されます。 （例：`openspec init`）
- `/opsx:...` コマンドは **AI アシスタントのチャット**で実行されます。 （例：`/opsx:propose`）

端末に `/opsx:propose` と入力しても何も起こらない場合は、このページがその理由です。あなたは OpenSpec の間違った半分について話しているのです。スラッシュ コマンドは端末コマンドではありません。これらは、通常「ログイン フォームの追加」と入力するのと同じチャット ボックスで、AI コーディング アシスタントに与える指示です。

この 1 つの違いが、新規ユーザーにとって最も一般的な障害となるため、それを明確にしましょう。

## 2 つの半分

OpenSpec は 2 つの役割を兼ね備えた 1 つのプロジェクトです。

**CLI (ターミナル半分)。** インストールしてシェルから実行する `openspec` という名前のプログラム。プロジェクトを設定し、変更をリストして検証し、ダッシュボードを表示し、完了した作業をアーカイブします。これらを iTerm、VS Code ターミナル、PowerShell など、`git` または `npm` を実行する場所に入力します。

```bash
openspec init        # set up OpenSpec in this project
openspec list        # see active changes
openspec view        # open the interactive dashboard
```

**スラッシュ コマンド (半分はチャット)。** AI アシスタントに入力する `/opsx:propose` や `/opsx:apply` などの短いコマンド。これらは、AI に OpenSpec のワークフローに従うように指示します。つまり、提案書を作成し、仕様書を作成し、タスク リストから構築し、完了したらアーカイブします。これらを、Claude Code、Cursor、Windsurf、Copilot、または使用するアシスタントに入力します。

```text
/opsx:propose add-dark-mode    (typed in your AI chat)
/opsx:apply                    (typed in your AI chat)
/opsx:archive                  (typed in your AI chat)
```

メンタル モデルを 1 枚の図で示します。

```text
        YOUR TERMINAL                         YOUR AI ASSISTANT'S CHAT
   ┌──────────────────────┐               ┌──────────────────────────────┐
   │  $ openspec init     │   installs    │  /opsx:propose add-dark-mode  │
   │  $ openspec list     │  ──────────►  │  /opsx:apply                  │
   │  $ openspec view     │   commands    │  /opsx:archive                │
   └──────────────────────┘    & skills   └──────────────────────────────┘
        run openspec here                       run /opsx:* here
```

矢印に注目してください。ターミナルで `openspec init` を実行すると、AI ツールにスラッシュ コマンドが *インストール*されます。端末の半分がチャットの半分を設定します。その後、日々の運転はほとんどチャットで行われます。

## 「対話モードを開始するにはどうすればよいですか?」

**開始するための個別のインタラクティブ モードはありません。** この質問はよく寄せられるので、明確な答えが必要です。

特別な OpenSpec モードに入る必要はありません。いつものように AI コーディング アシスタントを開き、チャットにスラッシュ コマンドを入力するだけです。スラッシュ コマンドは、OpenSpec に「入る」方法です。アシスタントはそれを認識し、一致する OpenSpec スキルをロードし、ワークフローに従い始めます。

したがって、実際の指示は次のとおりです。

1. プロジェクトで AI コーディング アシスタント (Claude Code、Cursor、Windsurf など) を開きます。
2. チャットに、他のリクエストを入力するのと同じ場所に「`/opsx:propose`」と入力します。
3. オートコンプリートを確認します。OpenSpec がインストールされている場合は、スラッシュを入力すると、`/opsx:propose`、`/opsx:apply`、およびその友達が表示されます。

それでおしまい。モードを切り替える必要もなく、デーモンを起動する必要もなく、別のウィンドウも必要ありません。

真にインタラクティブなものが 1 つあり、それは `openspec view` です。仕様と変更を参照するためのダッシュボードが開きます。しかし、それはビューアであり、提案して構築するものではありません。建設はチャットのスラッシュ コマンドによって行われます。

## この分割が存在する理由

OpenSpec が 25 以上の異なる AI ツールで動作する理由を説明しているため、理解する価値があります。

CLI は **エンジン** です。これは、変更フォルダーがどのようなものであるか、どのアーティファクトがどのアーティファクトに依存するか、仕様差分を信頼できるソースにマージする方法などのルールを知っています。それはどこでも同じです。

スラッシュ コマンドは **ステアリング ホイール** であり、AI ツールごとに若干異なるものがあります。クロード・コードではそれらをコマンドと呼んでいます。カーソルとウィンドサーフィンには独自の形式があります。一部のツールではそれらをスキルと呼びます。 `openspec init` を実行すると、OpenSpec は選択したツールごとに適切な種類のファイルを生成するため、どのアシスタントを選択しても同じ `/opsx:propose` インテントが機能します。

この設計の強みは、ワークフローを一度学習すれば、それをさまざまなツールに適用できることです。トレードオフ: コマンドの正確な構文はツールによって若干異なる可能性があります。これについては次のセクションで説明します。

## ツール別のスラッシュ コマンド構文

意図はどこでも同じです。句読点が違います。アシスタントに合ったフォームを使用してください。

|ツール |入力方法 |
|------|-----------------|
|クロード・コード | `/opsx:propose`、`/opsx:apply` |
|カーソル | `/opsx-propose`、`/opsx-apply` |
|ウィンドサーフィン | `/opsx-propose`、`/opsx-apply` |
| GitHub コパイロット (IDE) | `/opsx-propose`、`/opsx-apply` |
|オーマイパイ | `/opsx-propose`、`/opsx-apply` |
|キミ・クリ |スキルスタイル、例: `/skill:openspec-propose` |
|トレイ | `/opsx-propose`、`/opsx-apply` |

ほとんどのツールはコロン形式 (`/opsx:propose`) またはダッシュ形式 (`/opsx-propose`) を使用します。いくつかのツールでは、OpenSpec をスラッシュ コマンドではなく名前付きスキルとして表示します。名前でスキルを呼び出す場合。どのファイルがどこに書き込まれるかを正確に含むツールごとの完全なリストは、[サポートされているツール](supported-tools.md).

疑問がある場合は、AI チャットにスラッシュを入力し、オートコンプリートを確認してください。ツールは期待する形式を表示します。

## コマンドがどのようにしてそこに到達したか: スキルとコマンド

`openspec init` (または `openspec update`) を実行すると、AI ツールがワークフローを見つけられるように、OpenSpec は小さなファイルをプロジェクトに書き込みます。ツールと設定に応じて、これらは **スキル**、**コマンド**、またはその両方です。

- **スキル**は`.claude/skills/openspec-*/SKILL.md`のような場所にあります。これらは、新たなクロスツール標準であり、アシスタントが自動検出する命令のフォルダーです。
- **コマンド**は、`.claude/commands/opsx/<id>.md` のような場所にあります。これらは古いツールごとのスラッシュ コマンド ファイルです。

ツールがどちらを使用するかを気にする必要はありません。スラッシュコマンドを入力するだけで機能します。ただし、これらのファイルが存在することを知っておくと、何か問題が発生したときに役立ちます。コマンドが消えた場合は、通常、これらのファイルが見つからないか古いことを意味し、`openspec update` はファイルを再生成します。

ツールごとの正確なパスについては、[サポートされているツール](supported-tools.md)]を参照してください。また、古いコマンドのみのアプローチがスキルにどのように置き換えられるかについては、[移行ガイド](migration-guide.md)]を参照してください。

## インストールされていることを確認する

クイックチェック、早い順:

1. **AI チャットにスラッシュを入力します。** `/opsx` と入力し始め、オートコンプリートの候補を確認します。それらが表示されれば完了です。
2. **ファイルを探します。** クロード コードの場合、`.claude/skills/` に `openspec-*` フォルダーが含まれていることを確認します。他のツールは独自のディレクトリを使用します ([サポートされているツール](supported-tools.md) にリストされています)。
3. **セットアップを再実行します。** プロジェクト ルートから `openspec update` を実行します。これにより、設定したツールのスキル ファイルとコマンド ファイルが再生成されます。
4. **アシスタントを再起動します。** 多くのツールは起動時にスキルとコマンドをスキャンするため、新しいウィンドウが表示されない場合があります。

## どのようなコマンドがあるのでしょうか?

デフォルトでは、OpenSpec はスラッシュ コマンドの **コア** セットをインストールします。

- `/opsx:explore`: 変更をコミットする前に AI を使ってアイデアを検討します (確信がない場合に最適な最初のステップ)
- `/opsx:propose`: 変更を作成し、そのすべての計画成果物を 1 つのステップでドラフトします。
- `/opsx:apply`: タスク リストを処理して変更を構築します。
- `/opsx:sync`: 変更による仕様更新をメイン仕様にマージします (通常は自動)
- `/opsx:archive`: 変更を完了してファイルに保管します

良いデフォルトのリズム: 何をすべきか考えているときは `explore`、次に `propose`、`apply`、`archive`。 [Explore First](explore.md) ガイドでは、その最初のステップがなぜ効果があるのか​​を説明しています。

より細かく制御したい人向けの **拡張** セットもあります (`/opsx:new`、`/opsx:continue`、`/opsx:ff`、`/opsx:verify`、`/opsx:bulk-archive`、`/opsx:onboard`)。 `openspec config profile` でオンにしてから、`openspec update` で適用します。

こういったことは初めてですか? `/opsx:onboard` (拡張セット内) では、独自のコードベースでの完全な変更を手順ごとに説明し、各ステップを説明します。それは可能な限りフレンドリーな紹介です。

各コマンドの動作の詳細については、「Commands](commands.md).いつどれに到達するかについては、「Workflows](workflows.md).

## クリーンな最初の実行

これをまとめると、シーケンス全体と、各ステップが発生する場所によってラベルが付けられたものが以下になります。

```text
TERMINAL   $ npm install -g @ayumuwall/openspec@latest
TERMINAL   $ cd your-project
TERMINAL   $ openspec init
              (installs slash commands into your AI tool)

AI CHAT      /opsx:explore
              (optional: think the idea through with the AI first)

AI CHAT      /opsx:propose add-dark-mode
              (AI drafts proposal, specs, design, tasks)

AI CHAT      /opsx:apply
              (AI builds it, checking off tasks)

AI CHAT      /opsx:archive
              (change is merged into your specs and filed away)
```

セットアップする ターミナルでの 2 つの手順。それからあなたはチャットに住んでいます。それがリズムです。
