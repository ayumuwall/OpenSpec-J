# OpenSpec ドキュメント

OpenSpec ドキュメントの入口です。

OpenSpec は、あなたと AI コーディングアシスタントが **コードを書く前に、何を作るか合意する**ための道具です。あなたが変更内容を説明し、AI が短い仕様とタスクリストを下書きし、同じ計画を確認してから実装に入ります。途中で「AI が違うものを作っていた」と気づくリスクを減らします。

最初に読むなら、次の 2 ページです。

1. [はじめに](getting-started.md): インストール、初期化、最初の変更までを一通り進めます。
2. [コマンドの仕組み](how-commands-work.md): `/opsx:propose` をどこに入力するかを説明します。ヒント: ターミナルではなく AI チャットです。ここは多くの人が一度つまずきます。

2 つ目は見た目以上に重要です。OpenSpec には、ターミナルで実行するコマンドラインツールと、AI アシスタントに渡すスラッシュコマンドの 2 種類があります。どちらをどこで使うか分かっていれば、よくある混乱を避けられます。

> **最初に身につけたい習慣:** 何を作るべきか曖昧なときは、`/opsx:explore` から始めてください。成果物やコードを作る前に、コードを読み、選択肢を整理し、曖昧なアイデアを具体的な計画に近づけます。詳しくは [まずは探索する](explore.md) を参照してください。

## 目的別に読む

**初めて使います。** [はじめに](getting-started.md) から始め、次に [コアコンセプトの概要](overview.md) を読んでください。分からない用語があれば [FAQ](faq.md) と [用語解説](glossary.md) が役立ちます。

**問題はあるが、計画はまだありません。** よくある状況です。[まずは探索する](explore.md) を読んでください。何かを作る前に `/opsx:explore` で AI と一緒に考えます。

**既存の大きなコードベースで使いたいです。** 最初から全体を文書化する必要はありません。[既存プロジェクトで OpenSpec を使う](existing-projects.md) では、ブラウンフィールドのコードベースに無理なく導入する方法を説明しています。

**とにかく動かしたいです。** [インストール](installation.md)して `openspec init` を実行し、[コマンドの仕組み](how-commands-work.md)を読んで、最初のスラッシュコマンドを正しい場所に入力できるようにしてください。[AI支援インストール用プロンプト](installation.md#aiアシスタントでインストール)を使って、セットアップをアシスタントへ任せることもできます。

**例で学びたいです。** [例とレシピ](examples.md) では、小さな機能、バグ修正、リファクタリング、探索など、実際の変更を最初から最後まで説明します。

**AI が計画を作りました。次に何をすればよいですか？** まず読みます。[変更のレビュー](reviewing-changes.md) では、まだ修正コストが安い段階で方向違いを見つける方法を説明します。[良い仕様を書く](writing-specs.md) では、承認できる計画がどのようなものかを説明します。

**チームで使います。** [チームでの OpenSpec](team-workflow.md) では、変更がブランチ、プルリクエスト、レビューにどう対応するか、コードの前にチームメイトが計画をレビューする方法を説明します。

**古いワークフローから移行します。** [移行ガイド](migration-guide.md) では、何が変わったか、なぜ変わったか、既存の作業がどう扱われるかを説明します。

**チームの進め方に合わせて調整したいです。** [カスタマイズ](customization.md) では、プロジェクト設定、カスタムスキーマ、共有コンテキストについて説明しています。

**何かが壊れています。** [トラブルシューティング](troubleshooting.md) には、実際に起きやすい失敗と対処方法をまとめています。

## 30 秒版

```text
1. インストール   npm install -g @ayumuwall/openspec@latest
2. 初期化         cd your-project && openspec init
3. 探索           (AI チャットで)  /opsx:explore           ← 任意ですが、良い習慣です
4. 提案           (AI チャットで)  /opsx:propose add-dark-mode
5. 実装           (AI チャットで)  /opsx:apply
6. アーカイブ     (AI チャットで)  /opsx:archive
```

ステップ 1 と 2 はターミナルで実行します。残りは AI アシスタントのチャットで実行します。この分割だけは覚えてください。理由は [コマンドの仕組み](how-commands-work.md) で説明しています。ステップ 3 は任意ですが、迷ったときに `/opsx:explore` から始めるのは強い習慣です。
