# OpenSpec ドキュメント

いらっしゃいませ。ここは OpenSpec のすべての拠点です。

OpenSpec は、あなたと AI コーディング アシスタントが **コードを書く前に何を構築するかについて合意するのに役立ちます**。あなたが変更について説明し、AI が短い仕様とタスク リストの草案を作成し、二人で同じ計画を検討し、その後作業が開始されます。 AI が間違ったものを構築したことに途中で気づく必要はもうありません。

他に何も読んでいない場合は、次の 2 ページをお読みください。

1. [はじめに](getting-started.md): 最初の変更をインストール、初期化、出荷します。
2. [コマンドの仕組み](how-commands-work.md): 実際に `/opsx:propose` と入力する場所 (ヒント: ターミナルではなく AI チャット内)。これはほとんどの人が一度はつまずくでしょう。

2 番目の要素は、見た目よりも重要です。 OpenSpec には、ターミナルで実行するコマンド ライン ツールと、AI アシスタントに与えるスラッシュ コマンドの 2 つの部分があります。どれがどれであるかを知ることで、最もよくある混乱の瞬間を避けることができます。

> **最初に構築するための最良の習慣: 何を構築すればよいかわからないときは、`/opsx:explore` から始めてください。** これは、成果物やコードが存在する前に、コードを読み取り、選択肢を検討し、曖昧なアイデアを具体的な計画に研ぎ澄ます、ノーステーク パートナーです。 [Explore First](explore.md)] ガイドがそれを証明しています。

## 自分の道を選んでください

**私は初心者です。** [Getting Started](getting-started.md)] から始めて、次に [Core Concepts at a Glance](overview.md)] をざっと読んでください。何か不思議に思ったときは、[FAQ](faq.md)] と [用語集](glossary.md)] が近くにあります。

**問題はあるが、計画はありません。** これは一般的なケースであり、専用の回答があります: [Explore First](explore.md).何かを実行する前に、`/opsx:explore` を使用して AI でよく考えてください。

**既存の大きなコードベースがあります。** そのすべてを文書化していません。 [既存のプロジェクトで OpenSpec を使用する](existing-projects.md) は、大騒ぎすることなく実際のブラウンフィールド コードを開始する方法を示しています。

**それを機能させたいだけです。** [](installation.md) をインストールし、`openspec init` を実行して、[コマンドの仕組み ](how-commands-work.md)] を読んで、最初のスラッシュ コマンドが適切な場所に配置されるようにします。

**例によって学びます。** [例とレシピ](examples.md)] ページでは、小さな機能、バグ修正、リファクタリング、探索など、実際の変更を最初から最後まで説明します。

**AI が計画を作成したところです。さあどうするのですか?** 読んでください。 [Change](reviewing-changes.md) のレビューでは、まだ安いのに間違った方向に曲がる 2 分間のパスが示されており、[良い仕様の執筆 ](writing-specs.md) では、承認に値する計画がどのような構成になっているかが説明されています。

**私はチームで働いています。** [Team](team-workflow.md) の OpenSpec は、変更がブランチとプル リクエストにどのようにマッピングされるか、およびコードの前にチームメイトがどのように計画をレビューするかを示しています。

**私は古いワークフローから来ています。** [移行ガイド](migration-guide.md)] では変更内容とその理由が説明されており、既存の作業が安全であることが保証されています。

**チームのプロセスに合わせて変更したいです。** [カスタマイズ](customization.md)は、プロジェクト構成、カスタム スキーマ、および共有コンテキストをカバーします。

**何かが壊れています。** [トラブルシューティング](troubleshooting.md)は、人々が実際に遭遇した失敗と修正を収集します。

## 第 32 バージョン

```text
1. Install        npm install -g @ayumuwall/openspec@latest
2. Initialize     cd your-project && openspec init
3. Explore        (in your AI chat)  /opsx:explore           ← optional, but a great habit
4. Propose        (in your AI chat)  /opsx:propose add-dark-mode
5. Build          (in your AI chat)  /opsx:apply
6. Archive        (in your AI chat)  /opsx:archive
```

ステップ 1 と 2 は端末で行われます。残りは AI アシスタントのチャットで行われます。この分割は覚えておく価値のあることの 1 つであり、その理由は [コマンドの仕組み](how-commands-work.md)] で正確に説明されています。ステップ 3 はオプションですが、迷ったときに `/opsx:explore` から始めるのが最も価値のある習慣です。
