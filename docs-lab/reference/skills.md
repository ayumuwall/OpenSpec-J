スキルは 2 つの集合に分かれます。

- **Core**：既定でインストールされる、主要な計画ループです。
- **Optional**：[プロファイル](../customize/profiles.md)で追加した場合だけインストールされます。

| スキル                                                        | 役割                                                          | 種類     |
| ------------------------------------------------------------- | ------------------------------------------------------------- | -------- |
| [openspec-explore](#openspec-explore)                         | アイデアを変更提案にする前に検討する                          | Core     |
| [openspec-propose](#openspec-propose)                         | 変更提案とすべての計画アーティファクトを 1 手順で作成する     | Core     |
| [openspec-apply-change](#openspec-apply-change)               | 変更提案のタスクを実装する                                    | Core     |
| [openspec-update-change](#openspec-update-change)             | 変更提案の計画を修正する                                      | Core     |
| [openspec-sync-specs](#openspec-sync-specs)                   | 変更提案の仕様更新を`specs/`へマージする                      | Core     |
| [openspec-archive-change](#openspec-archive-change)           | 完了した変更提案をアーカイブへ移す                            | Core     |
| [openspec-new-change](#openspec-new-change)                   | 空のひな形として変更提案を開始する                            | Optional |
| [openspec-continue-change](#openspec-continue-change)         | 次の計画アーティファクトを 1 つずつ作成する                   | Optional |
| [openspec-ff-change](#openspec-ff-change)                     | 実装に必要な全アーティファクトを含む変更提案を 1 回で作成する | Optional |
| [openspec-verify-change](#openspec-verify-change)             | 実装が計画と一致するか確認する                                | Optional |
| [openspec-bulk-archive-change](#openspec-bulk-archive-change) | 複数の変更提案をまとめてアーカイブする                        | Optional |
| [openspec-onboard](#openspec-onboard)                         | 実際の変更提案を最初から最後まで進めてワークフローを学ぶ      | Optional |

## openspec-explore

アイデアを変更提案にする前に検討します。

| 契約     | 説明                                                                                                                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | トピック。アイデア、問題、比較対象、または文脈に沿って検討する既存の変更提案名です。指定しなければ explore モードに入ります。                                                                                    |
| **作成** | 既定では何も作成せず、読み取りと調査だけを行います。依頼すると、`openspec/changes/<name>/`配下の新しい変更提案、または既存の proposal、design、specs、tasks への更新として知見を記録します。コードは書きません。 |
| **応答** | 必須の出力がない自由な対話です。考えがまとまると、問題、アプローチ、未解決事項、次の手順を要約し、記録するか提案します。判断するのは利用者です。ここでは実装を開始しません。                                     |

## openspec-propose

変更提案とすべての計画アーティファクトを 1 手順で作成します。

| 契約     | 説明                                                                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | kebab-case の名前（`add-dark-mode`）または通常の説明。どちらもなければ質問します。                                                                                   |
| **作成** | `openspec/changes/<name>/`へ、スキーマが定義するすべてのアーティファクトを依存順に作成します（spec-driven：proposal、仕様差分、design、tasks）。コードは書きません。 |
| **応答** | 作成してレビュー可能になったアーティファクトと、次の手順を示します。そこで停止し、実装は`openspec-apply-change`まで待ちます。                                        |

## openspec-apply-change

変更提案のタスクを、完了またはブロックされるまで順に実装します。

| 契約     | 説明                                                                                                                                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | 任意の変更提案名（`add-auth`）。対象が曖昧な場合は、進行中の変更提案を一覧表示して選択を求めます。                                                                                                                                                        |
| **作成** | コード。各タスクに必要な最小限の変更をプロジェクトファイルへ加えます。変更提案内では tasks ファイルだけを変更し、完了したタスクを`- [ ]`から`- [x]`へ更新します。                                                                                         |
| **応答** | タスクごとの進捗と全体の完了数（N/M タスク完了）を示します。すべて完了すると`openspec-archive-change`を提案します。アーティファクト不足でブロックされた場合は`openspec-continue-change`を案内します。タスクが不明確な場合やエラー時は停止して確認します。 |

## openspec-update-change

変更提案の既存の計画アーティファクトを修正し、相互の整合性を維持します。

| 契約     | 説明                                                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | 任意の変更提案名と、希望する修正内容。修正内容を指定しない場合は整合性レビューを実行し、アーティファクト間の矛盾、欠落、重複を確認します。                     |
| **作成** | 新規作成はありません。既存のアーティファクトファイルだけを編集します。不足アーティファクトの作成は`openspec-continue-change`が担当します。コードは書きません。 |
| **応答** | 修正案を示し、確認後にアーティファクトを 1 つずつ書き込みます。最後に修正内容と次の手順を示します。実装は`openspec-apply-change`まで待ちます。                 |

## openspec-sync-specs

変更提案をアーカイブせず、その仕様更新を`specs/`へマージします。

| 契約     | 説明                                                                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | 任意の変更提案名。仕様差分の一部を指定すると、その仕様だけを同期できます。                                                                                  |
| **作成** | 仕様差分ごとに`openspec/specs/<capability-path>/spec.md`を編集または作成し、追加、変更、削除、改名された要件を本仕様へマージします。コードは書きません。    |
| **応答** | 更新後の仕様を検証し、追加、変更、削除、改名した要件を機能ごとに要約します。変更提案は進行中のままです。アーカイブは`openspec-archive-change`まで待ちます。 |

## openspec-archive-change

完了した変更提案をアーカイブへ移します。

| 契約     | 説明                                                                                                                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | 任意の変更提案名。                                                                                                                                                                                               |
| **作成** | 変更提案フォルダを`openspec/changes/archive/YYYY-MM-DD-<name>/`へ移します。名前がすでに日付で始まる場合は追加しません。承認すると、先に`openspec-sync-specs`で未同期の仕様差分を同期します。コードは書きません。 |
| **応答** | アーティファクトまたはタスクが未完了の場合は、アーカイブ前に警告して確認します。仕様差分がある場合は同期するか確認します。最後に名前、スキーマ、アーカイブ先、仕様同期状態、警告を要約します。                   |

## openspec-new-change

空のひな形から変更提案を開始します。

| 契約     | 説明                                                                                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **引数** | ケバブケースの名前（`add-user-auth`）または通常の説明。デフォルト以外のワークフローを使う場合だけ、スキーマ名も指定します。どちらも指定しない場合は、何を作りたいか確認します。                  |
| **作成** | 空のひな形として`openspec/changes/<name>/`を作成します。この時点ではアーティファクトもコードも作成しません。                                                                                     |
| **応答** | ひな形の名前と場所、ワークフローのアーティファクト順序、ステータス（0/N 完了）、最初のアーティファクトのテンプレートを示します。アーティファクトの作成は`openspec-continue-change`まで待ちます。 |

## openspec-continue-change

変更提案の次の計画アーティファクトを 1 つずつ作成します。

| 契約     | 説明                                                                                                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | 任意の変更提案名。特定できない場合は、最近更新された変更提案から選ぶよう求めます。                                                                                                     |
| **作成** | スキーマの順序で次に作成可能なアーティファクトを 1 つだけ、変更提案フォルダに作成します。1 回の実行につき 1 アーティファクトとし、コードは書きません。                                 |
| **応答** | 作成したアーティファクト、進捗（M 個中 N 個が完了）、新たに作成可能になったアーティファクトを示します。計画が完了した場合はその旨を伝え、実装は`openspec-apply-change`へ引き継ぎます。 |

## openspec-ff-change

変更提案と、実装に必要なすべての計画アーティファクトを一度に作成します。

| 契約     | 説明                                                                                                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **引数** | ケバブケースの名前または通常の説明。どちらも指定しない場合は確認します。指定した変更提案がすでに存在する場合は、代わりにその変更提案を続行するよう提案します。                                                                       |
| **作成** | `openspec/changes/<name>/`と、実装に必要なすべての計画アーティファクトを依存関係の順に作成します。仕様駆動では proposal、specs、design、tasks の順です。スキップ対象または条件付きのアーティファクトだけ除外し、コードは書きません。 |
| **応答** | 変更提案の名前と場所、作成した各アーティファクト、スキップした条件付きアーティファクトとその理由を示します。ここで停止し、実装は`openspec-apply-change`まで待ちます。                                                                |

## openspec-verify-change

実装が変更提案のアーティファクトと一致しているか確認します。

| 契約     | 説明                                                                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | 任意の変更提案名。特定できない場合は、tasks アーティファクトがある変更提案を一覧にして確認します。                                                                   |
| **作成** | 何も作成しません。変更提案のアーティファクトとコードベースを読み取り、検証結果だけを報告します。                                                                     |
| **応答** | 完全性、正確性、一貫性のスコアカード、重大、警告、提案に分けた問題と推奨事項、最後にアーカイブ可能かどうかの評価を報告します。内容を変更せず、アーカイブもしません。 |

## openspec-bulk-archive-change

複数の変更提案を一度にアーカイブします。

| 契約     | 説明                                                                                                                                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | ありません。進行中の変更提案を一覧にし、すべてを選ぶ選択肢も含めて、任意の数を選ぶよう求めます。進行中の変更提案がなければ、その旨を伝えて停止します。                                                                                                    |
| **作成** | アーカイブする変更提案ごとに`openspec/changes/archive/YYYY-MM-DD-<name>/`を作成します。名前がすでに日付で始まる場合は、その接頭辞を維持します。各変更提案の仕様差分は、先に`openspec-sync-specs`で同期します。コードは書きません。                        |
| **応答** | 変更提案ごとのステータス表と、バッチ全体に対する 1 回の確認を示します。その後、アーカイブ済み、スキップ、失敗に分けた要約と仕様同期の結果を報告します。2 つの変更提案が同じ仕様を変更する場合はコードベースを確認し、実装済みの差分を古い順に同期します。 |

## openspec-onboard

実際の変更提案を最初から最後まで進めながら、ワークフローを学びます。

| 契約     | 説明                                                                                                                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数** | ありません。コードベースを調べて取り組みやすい小さなタスクを提示し、その中から選ぶか、別のタスクを説明するよう求めます。                                                                 |
| **作成** | 選んだタスクについて実際の変更提案を作り、アーティファクトを 1 つずつ作成します。実装を確認した後に実際のコードを書き、最後に変更提案をアーカイブします。                                |
| **応答** | 調査、作成、各アーティファクトの作成、実装、アーカイブという一連の流れを、入力を待ちながら案内します。最後に要点を振り返り、`openspec-propose`を案内します。所要時間は約 15〜20 分です。 |
