# 変更メタデータ（.openspec.yaml）

> 各変更に保存するメタデータで、使用できるフィールドと検証ルール。

## 場所

各変更のメタデータは、アーティファクトと同じ`openspec/changes/<change-name>/.openspec.yaml`に保存します。変更を作成すると、`schema`と`created`を設定したファイルを書き込みます。

## フィールド

| キー                  | 型                    | 必須   | 動作                                                                            |
| --------------------- | --------------------- | ------ | ------------------------------------------------------------------------------- |
| `schema`              | 文字列                | はい   | この変更が従うワークフロースキーマ                                              |
| `created`             | 文字列、YYYY-MM-DD    | いいえ | 変更を作成した日付を記録します                                                  |
| `goal`                | 文字列                | いいえ | 変更で達成することを記録します                                                  |
| `affected_areas`      | 文字列のリスト        | いいえ | 変更が影響すると見込む領域を記録します                                          |
| `initiative`          | `store`と`id`のマップ | いいえ | この変更が属するイニシアチブを記録します                                        |
| `skip_specs`          | 真偽値                | いいえ | 仕様デルタがない変更であることを宣言し、デルタ 0 件での検証を許可します         |
| `retire_capabilities` | 真偽値                | いいえ | この変更によって空になる機能（capability）を archive が削除することを許可します |

### schema

この変更が従うワークフロースキーマです。変更の作成時に設定され、プロジェクト設定より優先されます。その後`openspec/config.yaml`が変わっても、変更では同じスキーマを使い続けます。有効な名前は[スキーマ](../schemas/index.md)を参照してください。

### initiative

この変更が属するイニシアチブを、ストア ID とイニシアチブ ID で指定します。どちらも kebab-case です。

```yaml
initiative:
  store: platform-specs
  id: unify-billing
```

`store`と`id`以外のキーは拒否されます。現在、このリンクを読み取るコマンドはありません。

### skip_specs

純粋なリファクタリング、ツール、ドキュメント変更など、仕様デルタを意図的に作らない変更であることを宣言します。設定すると、検証はデルタ 0 件を許可し、仕様ファイルを生成するはずのアーティファクトを完了済みとして扱います。`specs/`配下に仕様ファイルがある状態で設定すると検証エラーになります。デルタと archive への影響は[spec-driven](../schemas/spec-driven/index.md)を参照してください。

### retire_capabilities

archive が機能（capability）を廃止することを許可します。この変更の REMOVED デルタによって機能から最後の要件がなくなる場合、archive は処理を停止せず、その機能の本仕様を削除します。削除内容は Git からしか復元できないため、このフラグによって作成者が明示的に判断します。archive の動作は[spec-driven](../schemas/spec-driven/index.md)を参照してください。

## 例

設定済みの`.openspec.yaml`：

```yaml
schema: spec-driven
created: 2026-08-14
goal: API にマジックリンクログインを追加する
affected_areas:
  - auth
  - api
```

## 検証

コマンドがファイルを読み書きするたびに検証します。書き込み時の検証に失敗するとエラーになり、何も書き込みません。既存ファイルの読み取りは、YAML が不正、フィールドが契約に違反、またはスキーマ名が利用できない場合に失敗します。ファイルがないことはエラーではなく、変更にメタデータがないものとして扱います。

[config.yaml](config-yaml.md)とは異なり、不正な値を警告だけで除外することはありません。メタデータにエラーがあるとコマンドを停止します。ただし、不明なトップレベルキーだけは例外で、拒否せず無視します。
