# 2.1 へのアップグレード

> OpenSpec 2.1 のコーディングエージェント向けグローバルスキル対応と移行手順。

CLI を更新し、各リポジトリで `openspec update` を実行してください。スキルの保存先を一度確認し、回答するまでは何も変更しません。グローバルにインストールすると、マシン上の全プロジェクトで同じスキルを使えます。

## 変更点

Vercel の `skills` インストーラーは、さまざまなコーディングツールへスキルを導入する手段として広まりつつあります。OpenSpec もこれを採用し、インストーラーの保守を減らしてスキル自体の改善に注力します。

**スキルのグローバルインストール**により、コーディングエージェントは複数のプロジェクトで同じ OpenSpec スキルを利用できます。

## 保存先を選ぶ

OpenSpec スキルを保持しているリポジトリで `openspec update` を実行すると、次の選択肢が表示されます。

```text
このプロジェクトの OpenSpec スキルをどこに保存しますか？

❯ このプロジェクトに保持   スキルをこのリポジトリに保持します。
  グローバルに切り替え     このマシンの全プロジェクトで使えるようにスキルをインストールします。
```

選択するまでは何も変更しません。CI やエージェントからの実行では質問せず、現在の保存先でスキルを更新します。

## このプロジェクトに保持する

Enter を押すと、スキルをリポジトリに保持します。

1. 選択内容を記録する `openspec/config.yaml` をコミットします。他のメンバーには同じ質問を表示しません。

GitHub 上の Copilot エージェントがリポジトリ内のスキルを読む場合は、この方法を選んでください。後から `openspec init --scope global` で切り替えられます。

## グローバルに切り替える

多くのチームには、この方法を推奨します。スキルをマシンにグローバルインストールし、リポジトリ内のコピーを削除します。

1. ファイルの削除をコミットします。
2. 他のメンバーは pull 後に `openspec update` を実行し、マシンへのスキル導入を確認されたら**はい**を選びます。

スクリプトでは手順 2 の代わりに `openspec init --tools <ids>` を実行します。旧版はプロジェクト内のスキルにしか対応していないため、リポジトリを切り替える前に全員の CLI をアップグレードしてください。

## スクリプトでリポジトリを設定する

2.0 では、新しいリポジトリで `openspec init --tools claude` を実行すると、そのリポジトリにスキルを書き込んでいました。今後はグローバルにインストールします。プロジェクトのリポジトリに保持する場合は `--scope project` を付けてください。

```bash
openspec init --scope project --tools claude
```

## 更新前に確認する

- **組み込みスキルを編集している場合：** 更新は組み込みスキルのフォルダを置き換えます。編集内容と、その中に追加したファイルを先に保存してください。`openspec update --dry-run` で変更予定を確認できます。
- **`npx skills add` を実行済みの場合：** そのインストールを保持したまま `openspec update` を実行してください。

1.x から移行する場合は、[2.0 へのアップグレード](upgrade-to-2.md)も参照してください。
