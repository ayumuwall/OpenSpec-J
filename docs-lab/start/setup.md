# プロジェクトをセットアップする

> プロジェクトへ OpenSpec を追加し、init の作成内容を確認して調整する。

## OpenSpec の保存場所を選ぶ

- **リポジトリ内（既定）**：仕様と変更提案を、その対象コードと同じ場所に置き、コードと一緒にバージョン管理します。このページの残りでは、この構成を使用します。
- **ストア内**：複数リポジトリで使用する場合や、計画をコードのリポジトリから完全に分離する場合に使う、独立した計画リポジトリです。利用するリポジトリ間で共有します。[ストア（ベータ）](../multi-repo/stores.md)で、適した状況とセットアップ方法を説明します。

## プロジェクトを初期化する

CLI を[インストール](installation.md)したら、プロジェクトのルートで init を実行します。
ターミナルで次を実行します。

```bash
cd <your-project>
openspec init
```

init は使用する AI ツールを確認し、選択したツールのワークフローファイルを書き込んで結果を報告します。

```
OpenSpec のセットアップが完了しました

新規作成: Claude Code
.claude/ にスキル 6 個とコマンド 6 個を作成しました
設定: openspec/config.yaml（スキーマ: spec-driven）
```

新しいコマンドを有効にするため、IDE を再起動してください。

init は安全に再実行できます。

- セットアップ済みのツールには、`新規作成`ではなく`更新`と表示されます。
- init を再実行して新しいツールを選択すると、そのツールが追加されます。
- `--tools`フラグを指定すると選択画面を省略できます（[CLI リファレンス](../reference/cli.md)）。

## init がインストールするもの

init はプロジェクトに 2 つのものを作成します。

- リポジトリのルートに`openspec/`フォルダ
- AI ツールのフォルダ（`.agents/`、`.claude/`など）にワークフローファイル（スキルとコマンド）

ほかのソースと同様に、すべてコミットしてください。理由は[FAQ](../help/faq.md)で説明しています。
init はリポジトリ内のほかの内容を変更しません。旧バージョンの OpenSpec が残したファイルを
見つけた場合は、削除前に確認します。

### `openspec/`フォルダ

OpenSpec のすべてのアーティファクトは、プロジェクトルートのこのフォルダに配置されます。

```
openspec/
├── config.yaml     プロジェクト設定と AI 用のコンテキスト
├── specs/          仕様（現時点では空）
└── changes/        進行中の変更提案（現時点では空）
    └── archive/    完了した変更提案の移動先
```

[コンセプト](../guides/concepts.md)で 2 種類のアーティファクトを、
[プロジェクト設定](../customize/project-config.md)で`config.yaml`を説明しています。

### The workflow files (skills and commands)

これらは、作業中に使う操作を定義した OpenSpec ワークフローです。次は、多くのツールが使用する
共有`.agents/`フォルダへ、スキルとしてインストールした場合の構成です。

```
.agents/skills/
├── openspec-explore/              先にアイデアを検討する
├── openspec-propose/              変更提案を作成する
├── openspec-apply-change/         変更提案のタスクを実装する
├── openspec-update-change/        変更提案の計画を修正する
├── openspec-sync-specs/           変更提案の仕様更新を specs/ へ同期する
├── openspec-archive-change/       完了した変更提案をアーカイブへ移す
├── openspec-verify-change/        実装が計画と一致するか確認する（既定では含まれない）
└── openspec-bulk-archive-change/  複数の変更提案を一度にアーカイブする（既定では含まれない）
```

これは既定のセットに、任意のワークフローを 2 つ加えたものです。
[プロファイル](../customize/profiles.md)に全 12 ワークフローを掲載しています。

既定では、各ワークフローを 2 つの形式でインストールします。

- **スキル**（`openspec-apply-change`）：作業を依頼すると、エージェントが自動的に読み取る手順です。
- **コマンド**（Claude Code では`/opsx:apply`）：同じワークフローを短い名前で入力して開始する方法です。

2 つの形式は機能的に同じです。ワークフローのスキルとコマンドには、同じ手順が含まれます。

2 つの形式があるのは、コマンドが先に登場し、ツールごとに表記が異なるためです。スキルはツール間で
共有される新しい標準ですが、すべてのツールがスキルを直接呼び出せるわけではありません。
そのため、コマンドは該当するツールの開始方法として残っています。

一部のツールはスキル形式だけをインストールします。スキルを直接実行するツールでは、init が
コマンドを省略し、その旨を表示します（`コマンドをスキップしたツール: codex（skill を使用）`）。

OpenSpec はスキルを推奨しており、将来的にはコマンドを廃止する予定です。

#### インストール内容を変更する

対話式の選択画面で、配布形式とワークフローセットを変更できます
（[プロファイル](../customize/profiles.md)）。ターミナルで次を実行します。

```bash
openspec config profile
```

次はスキルだけに切り替える例です。

```
現在の profile 設定
  配信方式: both

? 何を設定しますか？ Delivery のみ
? Delivery mode（workflows のインストール方法）: Skills のみ

設定変更:
  delivery: both -> skills
? このプロジェクトに今すぐ変更を適用しますか？ (Y/n) y
```

「はい」と答えると、現在のプロジェクトへその場で適用します。ほかのプロジェクトでは、次回の
`openspec update`時に適用されます。この設定はマシンごとのグローバル設定です。

セットアップは完了です。[クイックスタート](quickstart.md)で、最初の変更提案をここから進めます。
